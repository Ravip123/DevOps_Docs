🐳 Docker Build & Run

A focused, step-by-step tutorial on building images and running containers

1 Make sure you have a Dockerfile

Every docker build needs a Dockerfile in your project folder. Minimal example:

Dockerfile
# base image
FROM nginx:alpine

# copy files into the container
COPY . /usr/share/nginx/html

# document the port the app uses
EXPOSE 80

2 Build the image

From the folder containing the Dockerfile:

docker build -t myapp:latest .
PartMeaning
-t myapp:latesttag (name:version) for the image
.build context — folder Docker reads the Dockerfile from

3 Build variations

# custom Dockerfile name/path
docker build -t myapp:latest -f Dockerfile.prod .

# rebuild ignoring the layer cache
docker build --no-cache -t myapp:latest .

# pass a build-time variable
docker build --build-arg ENV=production -t myapp:latest .

# build for a specific platform (e.g. on Apple Silicon targeting amd64)
docker build --platform linux/amd64 -t myapp:latest .

4 Verify the image was built

docker images

You should see myapp listed with the latest tag, its size, and creation time.

5 Run the container

docker run -d --name myapp-container -p 8080:80 myapp:latest
FlagMeaning
-ddetached — runs in the background
--namegives the container a friendly name
-p 8080:80maps host port 8080 → container port 80

Visit http://localhost:8080 to see it live.

6 Run variations

# interactive shell instead of your app's default command
docker run -it myapp:latest sh

# pass environment variables
docker run -d -e NODE_ENV=production myapp:latest

# mount a local folder into the container
docker run -d -v $(pwd):/usr/share/nginx/html myapp:latest

# auto-remove the container once it stops
docker run --rm myapp:latest

# restart automatically unless manually stopped
docker run -d --restart unless-stopped myapp:latest
✅ Use --rm for quick tests you don't need to keep around.

7 Check it's running

docker ps

Lists running containers, their ports, and status. Add -a to see stopped ones too.

8 View logs and debug

docker logs myapp-container       # view output
docker logs -f myapp-container    # follow live
docker exec -it myapp-container sh   # open a shell inside

9 Stop and remove the container

docker stop myapp-container
docker rm myapp-container
💡 Combine both in one go: docker rm -f myapp-container

10 Clean up images

docker rmi myapp:latest        # remove one image
docker image prune             # remove dangling/unused images
docker system prune -a         # remove everything unused (careful!)

11 Full cycle, one block

docker build -t myapp:latest .
docker run -d --name myapp-container -p 8080:80 myapp:latest
docker ps
docker logs -f myapp-container
# Ctrl+C to stop following logs
docker stop myapp-container
docker rm myapp-container

🐬 Bonus: Running MySQL in Docker

MySQL is available as an official image, so you don't need a Dockerfile to run it — just docker run with the right options.

12 Pull the MySQL image

docker pull mysql:8.0

Using a fixed version tag (like 8.0) instead of latest avoids surprise upgrades.

13 Run a MySQL container

docker run -d \
  --name mysql-db \
  -e MYSQL_ROOT_PASSWORD=rootpass \
  -e MYSQL_DATABASE=mydb \
  -e MYSQL_USER=appuser \
  -e MYSQL_PASSWORD=apppass \
  -p 3306:3306 \
  -v mysql-data:/var/lib/mysql \
  mysql:8.0
FlagMeaning
MYSQL_ROOT_PASSWORDrequired — sets the root password
MYSQL_DATABASEcreates a database automatically on first start
MYSQL_USER / MYSQL_PASSWORDcreates a non-root user with access to that database
-p 3306:3306exposes MySQL's default port to the host
-v mysql-data:/var/lib/mysqlnamed volume so data survives container removal
✅ The named volume is important — without it, all your data disappears when the container is removed.

14 Check it's healthy

docker ps
docker logs -f mysql-db

Wait for a line like ready for connections in the logs before connecting.

15 Connect to MySQL

# from inside the container, using the mysql client bundled in the image
docker exec -it mysql-db mysql -u root -p

# or connect as the app user
docker exec -it mysql-db mysql -u appuser -p mydb

# from your host machine (needs a local mysql client installed)
mysql -h 127.0.0.1 -P 3306 -u appuser -p mydb

16 Backup and restore data

# dump database to a file on the host
docker exec mysql-db sh -c 'exec mysqldump -u root -p"rootpass" mydb' > backup.sql

# restore from a dump file
docker exec -i mysql-db sh -c 'exec mysql -u root -p"rootpass" mydb' < backup.sql

17 Stop, remove, and clean up

docker stop mysql-db
docker rm mysql-db

# data is safe in the volume — remove it only if you really want to wipe the database
docker volume rm mysql-data

18 MySQL with Docker Compose

Easier to manage than a long docker run command, especially alongside an app service:

docker-compose.yml
services:
  db:
    image: mysql:8.0
    container_name: mysql-db
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: rootpass
      MYSQL_DATABASE: mydb
      MYSQL_USER: appuser
      MYSQL_PASSWORD: apppass
    ports:
      - "3306:3306"
    volumes:
      - mysql-data:/var/lib/mysql

volumes:
  mysql-data:
docker compose up -d
docker compose logs -f db
docker compose down        # stops and removes container, keeps the volume

🌐 Docker Networking

Create custom networks so containers can talk to each other by name.

19 Create a network

docker network create mynet
# with a specific driver (bridge is default, most common for a single host)
docker network create --driver bridge mynet

# with a custom subnet
docker network create --subnet=172.20.0.0/16 mynet
✅ Containers on the same custom network can reach each other using their container name as a hostname — no need to expose ports to the host for that.

20 List and inspect networks

docker network ls

Shows all networks (bridge, host, none, plus any custom ones).

docker network inspect mynet

Shows subnet, gateway, and which containers are currently attached, with their IPs.

# quick one-liner to see just a container's network settings
docker inspect -f '{{json .NetworkSettings.Networks}}' myapp-container

21 Attach containers to a network

# run a new container directly on the network
docker run -d --name myapp-container --network mynet -p 8080:80 myapp:latest
docker run -d --name mysql-db --network mynet -e MYSQL_ROOT_PASSWORD=rootpass mysql:8.0

# connect an already-running container to a network
docker network connect mynet myapp-container

# disconnect a container from a network
docker network disconnect mynet myapp-container

With both containers on mynet, your app can connect to MySQL using the hostname mysql-db instead of an IP address.

22 Remove a network

docker network rm mynet
💡 A network can only be removed once no containers are attached to it. Stop/remove or disconnect them first.

🧹 Cleanup Commands — By Type

Separate cleanup for containers, images, and networks so you control exactly what gets removed.

23 Clean up containers

# remove one specific stopped container
docker rm myapp-container

# force remove even if it's running
docker rm -f myapp-container

# remove ALL stopped containers
docker container prune

# remove all stopped containers without confirmation prompt
docker container prune -f

# remove every container, running or not (careful!)
docker rm -f $(docker ps -aq)

24 Clean up images

# remove one specific image
docker rmi myapp:latest

# force remove (e.g. if used by a stopped container)
docker rmi -f myapp:latest

# remove dangling images only (untagged leftovers from builds)
docker image prune

# remove ALL unused images, not just dangling ones (careful!)
docker image prune -a

# remove every image on the system
docker rmi -f $(docker images -aq)

25 Clean up networks

# remove one specific custom network
docker network rm mynet

# remove all unused (no containers attached) custom networks
docker network prune

# without confirmation prompt
docker network prune -f
💡 Docker won't let you remove the built-in bridge, host, or none networks — that's expected.

26 Everything at once (nuclear option)

# check what's using space first
docker system df

# remove stopped containers, dangling images, unused networks, build cache
docker system prune

# also remove unused images AND volumes — irreversible data loss risk
docker system prune -a --volumes
⚠️ --volumes deletes named volumes too — including your MySQL data if it's not attached to a running container. Use with caution.
