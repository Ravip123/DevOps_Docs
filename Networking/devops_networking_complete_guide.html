1. Networking Mental Model

The core question: When machine A talks to machine B, you need to know who B is (IP/DNS), where B is (routing), how to reach it (protocol/port), and whether security allows it (firewall/SG/NACL).
Application → DNS → IP → Route → ARP/neighbor discovery → TCP/UDP → Port → Firewall → Application ↓ packets cross switches/routers/NAT/load balancers
IP
Identifies a network interface/address.
Subnet
Defines an IP range and network boundary.
Route
Tells a device where to send traffic.
Port
Identifies a service/application endpoint.
DNS
Maps names such as example.com to IPs.
Firewall
Allows or denies traffic based on rules.

4. IP Addressing

IPv4

IPv4 uses 32 bits, normally written as four decimal octets: 192.168.1.10. Each octet ranges from 0–255.

RangePurpose
10.0.0.0/8Private
172.16.0.0/12Private
192.168.0.0/16Private
127.0.0.0/8Loopback
169.254.0.0/16Link-local/APIPA
0.0.0.0Unspecified / default route context
255.255.255.255IPv4 limited broadcast

Public vs Private

A private IP is intended for internal networks and is not globally routable on the public Internet. A public IP can be Internet-routable. NAT commonly connects private address space to public addressing.

IPv6

IPv6 uses 128 bits, e.g. 2001:db8::10. It provides a vastly larger address space and has no IPv4-style broadcast.

6. CIDR — Classless Inter-Domain Routing

CIDR notation is network/prefix. Example: 10.20.0.0/16 means the first 16 bits are network bits.

/8
24 host bits → 16,777,216 total addresses
/16
16 host bits → 65,536 total
/24
8 host bits → 256 total
/32
One exact IPv4 address

Host formula

Total IPv4 addresses = 2^(32 - prefix)

Traditional usable hosts = 2^(32-prefix) - 2

Why /32 matters in DevOps

A /32 commonly represents one exact host in allowlists, routes, VPN rules or security rules. In AWS Security Groups, a single IPv4 source is commonly written as x.x.x.x/32.

Route summarization

Multiple networks can sometimes be represented by a larger aggregate route. This reduces routing-table size and simplifies operations, provided the summarized range is correct.

VLSM

Variable Length Subnet Masking means using different prefix lengths according to capacity needs.

10.0.0.0/16
├── 10.0.0.0/20     large application tier
├── 10.0.16.0/22    medium tier
├── 10.0.20.0/24    small service tier
└── 10.0.21.0/28    tiny management segment
Production principle: Do not allocate giant flat subnets simply because addresses are cheap. Plan growth, failure domains, routing, security boundaries and IP overlap before choosing CIDRs.

8. Routing

A route generally contains a destination prefix and a next hop/interface/target. Routers choose the most specific matching route (longest-prefix match).

Destination       Next hop
10.0.0.0/16       local
10.0.20.0/24      router-A
0.0.0.0/0         Internet/NAT gateway

Default route

0.0.0.0/0 matches IPv4 destinations that do not have a more specific route.

Routing example

Client 10.0.1.10 | | route for 10.0.2.0/24 v Router | v Server 10.0.2.20

Static vs dynamic routing

StaticManually configured; predictable and simple for small/specific paths.
DynamicProtocols such as BGP/OSPF exchange route information; useful at scale.

10. DNS

DNS translates names to records. A typical request may involve a client resolver, recursive resolver, root servers, TLD servers and an authoritative DNS server.

Production DNS issues

  • Wrong record or zone.
  • TTL/cache delaying changes.
  • Private/public DNS confusion.
  • Resolver failure.
  • Split-horizon DNS returning different answers internally and externally.
  • Application connecting to an old IP after deployment.

11. ARP, ICMP & DHCP

ARP

In IPv4 LANs, ARP discovers the MAC address associated with a local IPv4 address. Modern Linux also uses the broader neighbor subsystem to manage L2/L3 neighbor information.

ICMP

Used for network control and diagnostics. ping commonly uses ICMP Echo Request/Reply. Traceroute can use ICMP, UDP or TCP depending on implementation/options.

DHCP

Automatically provides network configuration such as IP address, subnet mask/prefix, gateway and DNS. Remember DORA: Discover → Offer → Request → Acknowledge.

12. NAT

Network Address Translation changes source and/or destination addressing as traffic crosses a boundary.

Private clients 10.0.1.10:51000 ─┐ 10.0.1.11:51001 ─┼──> NAT ──> Public IP:ephemeral-port ──> Internet 10.0.1.12:51002 ─┘

Common types

  • SNAT: changes source address, common for private → Internet.
  • DNAT: changes destination address, common in port forwarding/load-balancing patterns.
  • PAT: many private connections share one public IP through different ports.

AWS NAT Gateway

A private subnet can route Internet-bound traffic to a NAT Gateway in a public subnet. The NAT Gateway uses a public address for outbound Internet connectivity while preventing unsolicited inbound Internet connections to the private instances through that NAT path.

13. Network Security

Firewall thinking

For any failed connection ask: source IP → destination IP → protocol → destination port → route → security policy → listener → application response.

ControlTypical role
Security GroupStateful virtual firewall associated with AWS resources such as ENIs/instances.
NACLStateless subnet-level traffic control in AWS.
Host firewalliptables/nftables/ufw/firewalld on the machine.
WAFHTTP-aware filtering for web applications.
Network firewallCentralized network inspection/filtering use cases.
Least privilege: Avoid 0.0.0.0/0 for sensitive ports such as databases and SSH unless there is a deliberate, protected architecture that requires it.

Public vs private subnet in AWS

A subnet is commonly called public when its route table has a route to an Internet Gateway. A subnet is commonly called private when it has no direct Internet Gateway route; it may use a NAT Gateway for outbound Internet access.

Security Group example

ALB-SG:
  inbound TCP 443 from 0.0.0.0/0

APP-SG:
  inbound TCP 8080 from ALB-SG
  outbound as required

DB-SG:
  inbound TCP 3306 from APP-SG
  NOT from 0.0.0.0/0

End-to-end web request

  1. Client resolves app.example.com using DNS.
  2. Client connects to the ALB public address on TCP 443.
  3. ALB terminates TLS or passes TLS through, depending on design.
  4. ALB selects a healthy target.
  5. Target SG permits traffic from the ALB SG on the application port.
  6. Application reaches the database over a private route.
  7. DB SG permits only the application tier.
  8. Private application instances use NAT Gateway or VPC endpoints for required outbound AWS/Internet access.

18. Production Troubleshooting Method

The 7-layer practical checklist

  1. Application: Is the process running? Check logs, health endpoint, dependencies.
  2. Port: Is the expected port listening? ss -lntup.
  3. Host firewall: UFW/nftables/iptables/security agent.
  4. Destination security: AWS SG/NACL/WAF/network firewall.
  5. Routing: ip route, cloud route tables, peering/TGW/VPN.
  6. DNS: Correct record, resolver, private/public zone, TTL.
  7. Packets: Use flow logs, tcpdump, load-balancer logs and packet-level evidence.

For production, combine metrics, logs and traces. Network-specific evidence may include VPC Flow Logs, load-balancer access logs, application logs, DNS query logs, host socket state and packet captures.

19. Production Architectures

Highly available AWS 3-tier pattern

Route 53 | Internet / DNS | ALB :443 / \ AZ-A AZ-B Public/ALB Public/ALB | | Private App Private App | \ / | | \ / | +--- Database ----+ Multi-AZ Private outbound: App → NAT Gateway / VPC Endpoints Security: Internet → ALB only ALB → App only App → DB only

DevOps networking principles

  • Use multiple Availability Zones for critical services.
  • Keep databases private.
  • Use security groups based on workload identity rather than broad IP ranges where possible.
  • Use private connectivity/endpoints for AWS services when appropriate.
  • Plan non-overlapping CIDRs before connecting VPCs/on-prem networks.
  • Automate network configuration with IaC such as Terraform/CloudFormation.
  • Monitor flow, latency, errors, DNS and saturation.
  • Document ports and traffic flows.

20. Interview Questions & Answers

1. What is an IP address?

An IP address is a logical network address used to identify an interface or endpoint at the network layer and enable packet routing.

2. What is a subnet?

A subnet is a defined range of IP addresses within a larger network. Subnetting divides an address space into smaller routing/security/organizational boundaries.

3. What is CIDR?

CIDR is classless notation that represents an IP network using a prefix length, such as 10.0.0.0/16.

4. What does /24 mean?

24 of the 32 IPv4 bits are network bits and 8 are host bits. It contains 256 IPv4 addresses; traditional usable host count is 254.

5. Difference between public and private IP?

Private addresses are intended for internal networks and are not globally routable. Public addresses can be Internet-routable.

6. What is a default gateway?

It is the next-hop router used when a destination does not match a more specific route in the host's routing table.

7. What is TCP's 3-way handshake?

SYN, SYN-ACK, ACK. It establishes the TCP connection state and synchronizes sequence numbers.

8. TCP vs UDP?

TCP provides a reliable ordered byte stream with connection management and congestion control. UDP provides datagrams with lower protocol overhead and no built-in reliability.

9. What is DNS?

DNS is a distributed naming system that maps names to records such as IP addresses and service information.

10. What is NAT?

NAT translates network addressing. SNAT commonly changes source addresses for outbound traffic; DNAT changes destinations.

11. What is a route table?

A route table contains destination prefixes and targets/next hops that determine where traffic is forwarded.

12. Security Group vs NACL in AWS?

Security Groups are stateful controls associated with network interfaces/resources. NACLs are stateless controls applied at the subnet boundary.

13. Why can't a private subnet directly access the Internet?

In a common AWS design, the private subnet has no direct route to an Internet Gateway. Outbound Internet traffic is routed to a NAT Gateway, which is in a public subnet.

14. Why is a NAT Gateway placed in a public subnet?

Because it needs a route to an Internet Gateway and a public address for Internet-bound outbound traffic.

15. What happens when you type https://example.com?

Typically: DNS resolution → route selection → TCP connection (or another transport such as QUIC/UDP for HTTP/3) → TLS negotiation → HTTP request → server/load balancer processing → response.

16. How do you troubleshoot "connection timed out"?

Check DNS, source/destination IPs, routes, SG/NACL/firewall rules, listener state, load balancer health, return path and packet evidence using flow logs/tcpdump.

17. How do you check whether port 8080 is listening on Linux?

Use ss -lntup | grep :8080. Then inspect the owning process and application logs.

18. ping works but curl fails. Why?

ICMP reachability does not prove TCP/HTTP reachability. Port 443/8080 could be blocked, the service may not listen, TLS may fail, a proxy may intervene, or the application may return an error.

19. DNS resolves but application is unreachable. What next?

Test the resolved IP/port, inspect routes and security controls, verify the listener, then test with curl/nc and inspect logs.

20. What is a /32?

A prefix containing one IPv4 address. It is commonly used to identify a single host in routes or allowlists.

21. What is longest-prefix match?

When multiple routes match a destination, the route with the most specific/longest prefix is preferred.

22. What is VLSM?

Variable Length Subnet Masking uses different subnet sizes within an address space to allocate addresses efficiently.

23. What is an ALB?

An AWS Application Load Balancer operates at the application layer and supports HTTP/HTTPS routing features such as host/path-based routing.

24. ALB vs NLB?

ALB is primarily Layer 7 HTTP/HTTPS-aware load balancing. NLB is Layer 4-oriented and is suited to TCP/UDP/TLS and workloads requiring high-performance connection handling.

25. What is VPC peering?

A private network connection between two VPCs that allows routing between their address spaces, subject to routes and security controls.

26. What problem does Transit Gateway solve?

It provides a central routing hub for connecting many VPCs and other network attachments, reducing a complex mesh of point-to-point connections.

27. Why avoid overlapping CIDRs?

Overlapping ranges make routing ambiguous or impossible across many network connections such as peering, VPNs and transit architectures.

28. What is a reverse proxy?

A server that accepts client requests and forwards them to backend services. It can provide TLS termination, routing, caching, authentication and load distribution.

29. What is a load balancer health check?

A periodic probe used to determine whether a backend target is capable of receiving traffic. A target can be network-reachable yet fail its application health check.

30. How would you secure an AWS database?

Keep it private, restrict its security group to the application tier, minimize exposed ports, use encryption/authentication, monitor access, and avoid public Internet exposure unless explicitly required.

31. How does Docker DNS help?

User-defined Docker networks provide service/container name resolution so containers can communicate using stable names rather than hard-coded container IP addresses.

32. What is a Kubernetes Service?

A stable virtual endpoint that selects pods and provides service discovery/load distribution across matching backends.

33. What is MTU?

Maximum Transmission Unit is the largest packet payload size that can be carried over a link without fragmentation at that layer. Incorrect MTU can cause intermittent connectivity, especially with tunnels.

34. What is asymmetric routing?

Traffic from A to B follows a different path from B to A. It can cause problems with stateful firewalls, troubleshooting and packet capture interpretation.

35. How would you investigate packet loss?

Establish whether loss occurs at the host, network segment, firewall, load balancer or destination. Compare ping/transport tests, interface counters, flow logs and packet captures, and check saturation/errors.

Final Production Mindset

Don't memorize networking only as definitions. In a DevOps interview or production incident, trace the traffic.

Source → Destination → DNS → Route → Security → Port → Listener → Protocol → Application → Dependency → Return path.

When you can draw the traffic path and explain every hop, networking becomes much easier to troubleshoot.
